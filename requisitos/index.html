    7 Requisitos de Software

    7.1 Lista de Requisitos Funcionais

    Os requisitos destacados em negrito foram implementados no produto.

    • RF C.1: Visualizar nichos de atuação da Nihon.
    • RF D.1: Visualizar produtos por nicho de atuação.
    • RF D.2: Visualizar produtos por marca.
    • RF D.3: Visualizar informações de um produto.
    • RF D.4: Visualizar produtos ativos
    • RF E.1: Acessar o WhatsApp da Nihon.
    • RF F.1: Solicitar orçamento de um produto.
    • RF F.2: Confirmar envio de pedido de orçamento.
    • RF F.3: Notificar o cliente quando o status do orçamento for atualizado.
    • RF G.1: Visualizar os fornecedores e parceiros.
    • RF H.1: Visualizar “Casos de Sucesso” de projeto finalizados pela Nihon.
    • RF I.1: Visualizar informações institucionais sobre a Nihon.
    • RF M.1: Visualizar produtos cadastrados.
    • RF M.2: Cadastrar novo produto.
    • RF M.3: Remover um produto do catálogo.
    • RF M.4: Editar informações de um produto.
    • RF N.1: Remover um caso de sucesso.
    • RF N.2: Visualizar caso de sucesso.
    • RF N.3: Cadastrar novo caso de sucesso.
    • RF N.4: Editar informações de um caso de sucesso existente.
    • RF O.1: Envio de Email com os dados do pedido de orçamento para a equipe da Nihon.
    • RF P.1: Gerenciar orçamentos.
    • RF P.2: Atualizar o status de um orçamento.
    • RF Q.1: Recuperar Senha de Administrador via e-mail.
    • RF Q.3: Fazer Logout do painel administrativo.

    7.2 Lista de Requisitos Não Funcionais

    Usabilidade (Usability) Foco na facilidade de uso, estética e experiência do usuário.

    • RNF J.2: Seguir um guia de estilo consistente, garantindo consistência visual.
    • RNF K.1: Garantir que a interface do painel administrativo seja bem explicativa.
    • RF L.1: O site deve garantir boa usabilidade em desktops, tablets e smartphones com design responsivo.
    • RF L.2: A responsividade deve garantir adaptação fluida iniciando em resoluções de 360px, com ajustes progressivos (breakpoints) para cobrir a maioria dos dispositivos móveis até 420px e superiores.

    Confiabilidade (Reliability) Foco na robustez, segurança e disponibilidade do sistema.

    • RF R.1: Armazenar as senhas utilizando um algoritmo de hash seguro (ex: bcrypt).

    Desempenho (Performance) Foco em tempo de resposta e velocidade.

    • RF L.1: O site deve garantir boa usabilidade em desktops, tablets e smartphones com design responsivo.

    Suportabilidade (Supportability) Foco na facilidade de manutenção, evolução e documentação.

    • RF R.2: Produzir artefatos de documentação.
    • RF R.3: Utilizar boas práticas do Next.js e de programação em geral.

    Restrições de Implementação e Padrões (+) Foco em tecnologias obrigatórias e padrões que limitam as escolhas de desenvolvimento.

    • RF A.1: O frontend deve ser desenvolvido em Next.js.
    • RF A.2: O backend deve ser implementado com a API Routes do Next.js.
    • RF A.3: O banco de dados deve ser PostgreSQL, gerenciado pela Supabase.
    • RF A.4: A aplicação deve ser hospedada na plataforma Vercel.
    • RF A.5: O desenvolvimento de componentes visuais deve seguir a abordagem Mobile-First, utilizando o framework TailwindCSS para estilização.
    • RF B.5: O site deve aplicar práticas de SEO (Search Engine Optimization) para garantir visibilidade nos mecanismos de busca.
